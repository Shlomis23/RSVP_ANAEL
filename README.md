# RSVP ANAEL

מערכת אישורי הגעה לבריתה של אנאל, עם טופס בעברית ועריכה מאותו דפדפן, ומסך ניהול באמצעות סיסמה בלבד.

פרטי האירוע: יום ראשון 18.10.2026 בשעה 19:30, אולם אצולת העמק בעפולה. המארחים: עדי ועדן תמיר. העיצוב מבוסס על ההזמנה שסופקה.

## הפעלה מקומית

נדרשים Node.js 22 ומעלה, npm וגישה לפרויקט Neon.

```sh
npm ci
neon link --project-id falling-morning-83495870 --branch production -y
neon checkout dev-rsvp-app
# אם אין ענף פיתוח: neon checkout dev-rsvp-app --create
npm run db:migrate
```

`neon.ts` מכיל את המדיניות שנבחרה: `defineConfig({})`. PostgreSQL בלבד; אין צורך ב־Neon Auth, באחסון אובייקטים או בשירות בתשלום נוסף לצורך המערכת הזו.

הוסיפו ל־`.env.local` את הערכים הבאים לצד משתני המסד ש־Neon הפיק:

```dotenv
APP_ORIGIN=http://127.0.0.1:3000
COOKIE_SECURE=false
EVENT_SLUG=anael
```

הגדירו את הסיסמה במסוף פרטי. הקלט מוסתר והסיסמה נשמרת כגיבוב scrypt בלבד:

```sh
npm run admin:password
npm run dev
```

פתחו `http://127.0.0.1:3000`. מסך הניהול נמצא ב־`/admin`. אין הרשמה ואין צורך באימייל. שינוי הגיבוב מבטל את כל סשני הניהול הקיימים. יש להפעיל מחדש את השרת אחרי החלפת הסיסמה.

## תהליכי האורחים

- אורח ממלא אישור אחד בדפדפן. בחזרה לקישור מאותו מכשיר ובאותו דפדפן, נטענת הרשומה הקיימת לעריכה.
- אין כפתור לאישור נוסף ואין העתקה או הפקה של קישור שחזור חדש.
- `activeRsvpId` נשמר מקומית לבחירת הרשומה בלבד. הרשאות העריכה נבדקות בשרת באמצעות עוגיית HttpOnly ושיוך לרשומה.
- סשן הדפדפן תקף 30 ימים. מחיקת נתוני הדפדפן, גלישה פרטית או שימוש בדפדפן אחר אינם משמרים את הזיהוי.
- בקשה חוזרת עם אותו `requestKey` מחזירה את אותה רשומה. בקשה חדשה בדפדפן שכבר משויך לאישור מקבלת `EXISTING_RSVP`; הממשק טוען את האישור הקיים ולא יוצר נוסף.
- עדכון מותנה ב־`expectedVersion`; גרסה ישנה מקבלת 409.
- `no` ו־`maybe` נשמרים עם כמות אפס. `yes` מוגבל ל־1–20 משתתפים.
- לתאימות עם קישורים שהופקו בעבר בלבד, מסלול claim הישן נשאר זמין. אין הפקה של קישורים חדשים ואין מחיקה של רשומות או הרשאות קיימות במסגרת השינוי.

## ניהול

הדשבורד כולל סיכומי הגעה, חיפוש, סינון, דפדוף, הוספה ועריכה ידנית, מחיקה עם אישור, היסטוריית פעולות וייצוא XLSX עם שעון ישראל.

כפילויות הן הצעות לסקירה: שם מנורמל זהה או דמיון של 85% ומעלה. אין איחוד אוטומטי ואין סכימת כמויות. המנהלת בוחרת אישור שיישמר; הרשומה השנייה מאורכבת וכל הרשאות העריכה שלה מבוטלות. הרשאות של האישור שהוסר אינן מועברות לאישור המנצח. סימון ״לא כפול״ נבחן מחדש לאחר שינוי גרסה.

מחיקה היא ארכוב: הרשומה מוסרת מהסיכומים ומהייצוא, נשמרת לצורך תיעוד, והרשאות האורח מבוטלות. מחיקה סופית לפי מדיניות שמירת הנתונים נעשית באמצעות כלי התחזוקה לאחר קביעת התקופה.

ברירת המחדל היא הרשמה פתוחה ללא מועד סגירה. אפשר לסגור ולפתוח הרשמה בדשבורד. מועד סגירה מפורש נתמך בשדה `registration_closes_at` וב־`PATCH /api/admin/event`.

## בדיקות

```sh
npm run typecheck
npm test

npx playwright install chromium
```

בדיקות האינטגרציה והדפדפן פועלות מול שרת מקומי ומסד Neon אמיתי בענף פיתוח בלבד. אסור להריץ אותן מול ענף production: בדיקות האינטגרציה משנות את מצב ההרשמה ומייצרות רשומות בדיקה.

אם עדיין אין סיסמת מנהלת בענף הפיתוח, אפשר להגדיר סיסמת בדיקה אקראית:

```sh
npx tsx scripts/prepare-tests.ts
npm run dev
# במסוף נוסף
npm run test:integration
npm run test:e2e
```

`prepare-tests.ts` מסרב להחליף סיסמה קיימת. אם כבר קיימת סיסמה, כתבו אותה רק בקובץ המקומי והמוחרג `work/.env.tests` תחת `TEST_ADMIN_PASSWORD`. אין להעלות קובץ זה ל־GitHub. צילומי מסך וקבצי trace של בדיקות מוחרגים גם הם מ־Git.

## פריסה ל־Vercel

אין בפרויקט פריסה אוטומטית של האפליקציה או מיגרציה לפרודקשן. לפני פרסום:

1. בדקו ואשרו את גרסת הניסיון.
2. החילו את המיגרציות על ענף production במכוון, באמצעות חיבור ישיר.
3. הגדירו בשרת `DATABASE_URL` של ענף production, `APP_ORIGIN` ככתובת HTTPS המדויקת, `EVENT_SLUG=anael` ואת `ADMIN_PASSWORD_HASH` שנבחר באופן פרטי. אל תגדירו משתנים סודיים עם `NEXT_PUBLIC_`.
4. פרסו ובדקו יצירה, עדכון וייצוא באתר עצמו. ב־Preview יש להשתמש בענף פיתוח. כתובות הפריסה והענף המדויקות שמספק Vercel נתמכות אוטומטית; אפשר להגדיר `APP_ORIGIN` מפורש לכתובת Preview נוספת. בפרודקשן `APP_ORIGIN` מפורש הוא חובה.

בפרודקשן העוגיות תמיד Secure ו־HttpOnly, עם `__Host-`, `Path=/` ו־SameSite=Lax. סשן מנהלת תקף שמונה שעות. כל פעולה מאומתת בשרת; כל בקשת שינוי מחייבת Origin תקף. אין להסתמך על הסתרת מסך הניהול.

המסד נגיש לשרת בלבד. RLS מופעל ו־PUBLIC אינו מקבל הרשאות לטבלאות. חיבור Neon של בעל המסד עוקף RLS, ולכן ההרשאות לרשומות ולאדמין נאכפות בנתיבי השרת ולא במדיניות לקוח. אין Data API ציבורי. החיבורים מוצפנים עם אימות תעודת TLS.

הגבלת קצב נשמרת במסד כדי לפעול גם בין כמה מופעי שרת. ב־Vercel היא משתמשת בכתובת IP שהפלטפורמה מספקת; בפריסה אחרת היא משתמשת במכסה משותפת, ולא סומכת על כותרת IP שהלקוח יכול לזייף. יש להתאים את זיהוי ה־IP אם נבחרת פלטפורמה אחרת.

## שמירת נתונים ותחזוקה

יש לקבוע עם המארחים כמה ימים לאחר האירוע לשמור נתונים אישיים. אין מחיקה אוטומטית ללא החלטה. הגדירו `RETENTION_DAYS` ופעילו תחילה תצוגה מקדימה:

```sh
npx tsx scripts/maintenance.ts
# רק לאחר בדיקת התוצאה ואישור המחיקה
npx tsx scripts/maintenance.ts --apply
```

הכלי מנקה סשנים שפגו, מפתחות שפגו ומכסות ישנות. מחיקת אישורים ותיעוד אישי מתבצעת רק לאחר תום האירוע ותקופת השמירה שהוגדרה. יש לתזמן אותו בסביבת האירוח לאחר קביעת המדיניות.
